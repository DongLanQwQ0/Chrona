# 统一动效与启动测量

本轮启动优化始于 0.13.76；0.13.78 根据设备反馈移除了与系统预测返回衔接不佳的 Activity 自定义转场。目标是首页尽快可用、玻璃控件保持一致、进入和退出有连续过渡。**尚不能确认 1 秒启动、实际帧率或视觉验收。**

## 项目巡检与处理

| 范围 | 发现的问题 | 本轮处理 |
| --- | --- | --- |
| 首页启动 | 壁纸准备时 OnPreDraw 拦截整个窗口，最多等 2500 ms | 删除首帧门闩，主题底色即时绘制；图片与模糊后台准备后同步淡入，模糊失败可显示原图 |
| 首页数据 | 首次恢复在 UI 线程查询数据库、核对历史并重复读取 revision | 首批首页数据与建库/升级在后台准备，一次读取有数量上限的首页数据；首批渲染复用 revision |
| 后台恢复 | 读取完整任务历史后筛选解析中记录 | 只查 processing 的 ID，后台核对；与 job claim 共用锁，条件更新不覆盖刚完成的记录 |
| 权限与更新入口 | 首次内容绘制前触发后续工作 | 首次内容绘制后再进入引导、权限、更新和维护；保留原触发规则 |
| 系统日历 | 每次恢复清空刷新时限；取消结果可能压制重查 | 保留有效缓存，取消/过期/失败结果失效时限；前台重新查询 |
| 引导、设置、备份、更新、弹窗按钮 | 实色主按钮、不同的次按钮背景、禁用态不明显 | 共用 acrylic 表面、主题文字、圆角、ripple、按压反馈与禁用文字颜色 |
| 表单与外观 | 输入框、下拉入口、复选/开关颜色不统一 | 使用公共表面及状态配色；小组件预览时间改用现有玻璃滚轮 |
| 引导步骤 | 正文即时替换 | 仅捕获可见滚动视口做短交叉淡化，固定头尾保持稳定，旋转仍恢复步骤及滚动位置 |
| 所有 Activity | 自定义进出动画与系统预测返回衔接不佳 | 0.13.78 移除 Activity 转场覆盖与资源，由系统完整管理进入、返回提交与取消 |
| 公共弹窗 | 有进入，退出直接消失 | 由窗口管理器统一 220 ms 进入、160 ms 退出，覆盖确认、取消、外部点击与返回 |
| 详情返回 | 总是注册拦截回调，普通浏览失去默认预测返回 | 仅有未保存编辑或正在保存时注册回调 |
| 详情横滑 | 双动画各遍历两棵 View 树；每次 MOVE 更新 | 每显示帧合并 MOVE，收集并复用玻璃控件，单个动画负责每帧刷新 |
| 记录与详情图片 | setImageURI 在 UI 线程解码 | 两个后台工作线程、按显示用途降采样、4 MiB 内存缓存、生命周期身份校验 |
| 局部主题切换 | 无效快照路径也分配 Bitmap | 先验证宿主，取消旧动画、清理旧快照并归一透明度后再捕获 |

Activity 转场完全交给系统管理，不再通过 Application 生命周期覆盖。页内动效和弹窗动画独立保留；Dock 主体切页时仍使用页面/高光共用进度，直接拖动 Dock 则从当前高光位置平滑追随手指。

## 测量与验收

区分 [Android 官方定义的 TTID 与 TTFD](https://developer.android.com/topic/performance/issues/launch-time)：前者是初始显示，后者通过 `reportFullyDrawn()` 报告主要内容已就绪。首页加载提示不报告完成；启用系统日程时等待当前窗口的查询结束与内容绘制。壁纸作为装饰独立加载。

`ChronaStartup` 的 `activity_ms` 只从 Activity 实例计时，不能代替包括进程启动成本的系统 TTFD。系统日志与应用就绪标记都存在时，脚本才判定该样本可用于验收；失败或缺失的样本不会算作达标。脚本不安装、不清数据、不更改引导和权限配置。

先在测试设备安装相同签名的当前版本，结束所有解析工作并完成引导/权限配置。以下命令会强制停止应用进行冷启动，不能用于正在解析真实任务的设备：

```powershell
python checks/measure_startup.py --adb 'F:\Android\Sdk\platform-tools\adb.exe' --serial '设备序列号' --samples 10 --target-ms 1000 --allow-force-stop --output build/startup-device.json
```

分别检查无壁纸/大壁纸、少量/较多历史、系统日程开关、首次安装/普通冷启动、热恢复。报告每次数据、中位数、P90、最大值；全部样本系统 TTFD ≤1000 ms 才表示该设备和条件下本次目标达成。设备性能、系统调度、首次数据库迁移与日历 Provider 耗时仍可能使结果超过目标；不要将一台设备的成绩推广为所有设备保证。

动画验收需覆盖：引导快速连点与旋转、打开/关闭及嵌套弹窗、详情未修改/有修改/保存中返回、Dock 短按/长按/拖动/取消、主体横滑、图片首次显示与返回缓存、暗色/自定义色/壁纸，以及系统动画缩放为 0。Activity 使用 [系统预测返回](https://developer.android.com/guide/navigation/custom-back/predictive-back-gesture)，需分别验收拖动、取消、提交及按钮返回；拦截未保存编辑时以数据保护为先。

普通返回/筛选的数据刷新和部分非首页页面仍沿用同步、有边界的查询；本轮没有改成全应用异步数据架构。实际耗时需要先取得设备剖析结果，再针对仍然超标的路径优化。
