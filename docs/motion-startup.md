# 统一动效与启动测量

## 选择栏跟随与点击反馈

拖动中高光位置直接跟随输入，尺寸继续使用弹簧；松手沿实际速度进行阻尼和落点预测。已知选中目标时立即让位置弹簧朝目标运动，不等待页面动画的中间进度。普通点按/短暂松手至少播放1.16倍的小幅脉冲后回到原尺寸，持续按住仍达到1.5倍；取消、多指接管及关闭动画不补播脉冲。统一控件保留完整长按包络，不能按短按尺寸缩减留白。

## 选择栏的统一用法

产品中正式称为“选择栏”，原生实现复用 DockNavigationLayout。顶部筛选、日历模式、任务类型及弹窗选项使用同一控件、高光物理和按压反馈。滚动弹窗内采用横向选项，选择时不重建整组视图；禁用状态不接收拖动或点击。标签使用原生单行自动字号适配窄屏与大字体，最大保留调用方字号，最小 8sp。

### 容器必须容纳完整动画

弹窗、滚动表单及靠近页面边缘的选择栏，使用 `dock.motionHost()` 加入布局。宿主根据最宽选项的布局权重，为整栏 1.1 倍、高光 1.5 倍及最多 0.75 个标准单元的越界伸展预留真实空间；中间容器不裁剪，滚动视口保留边界。不得以普通按钮的放大比例代替选择栏动画包络。验收覆盖首尾长按、拖出松手、快速甩动、窄屏及大字体。

选项行关闭 `LinearLayout` 的基线对齐。不同长度标签自动调整字号后仍共享单元格中心，不能让文字基线将末项及其高光推离选择栏。

筛选选项按文字长度分配宽度，日期自定义入口简称“自选”；不同宽度之间的高光按当前视觉位置插值，松手速度按所在区间换算，保持连续。

日程清除筛选时，筛选摘要连同底部间距以高度和透明度收起，下方选择栏随布局返回。快速反向操作从当前画面接续；初次创建、恢复页面及关闭动画时直接显示终态。日期范围的左右箭头分别切换前后区间，中间点击修改日期，横滑继续有效。

## 0.14.16 上限、阻力与并行切页

原生和网页 Dock 的外端绘制使用 `maximum * tanh(distance / maximum)`：边缘附近近似跟随原始距离，接近上限时逐渐减小增量，上限为标准高光宽度的 75%。保留半个标准宽度的内端锚点与物理边界回弹。

普通滑行指数阻尼由每秒 5 调至 7.5。放大过程的时间尺度为 1.5，因此刚度除以 1.5²、阻尼除以 1.5；释放缩回的参数保持原值，放大尺寸仍为高光 1.5、整栏 1.1。

松手时用同一生产物理积分函数预演阻尼与边缘回弹，立即选择预测落点并开始切页。页面回调不接管或清零正在进行的高光惯性，惯性结束只吸附到预测项目、不再次提交页面。日历移除等待视图条稳定后重建的逻辑，内容与高光并行切换。

## 0.14.15 切换与惯性

首页切页保留实时表面重绘，模糊壁纸使用 CLAMP 位图着色器，矩阵随窗口坐标更新，避免缓存整页导致离屏部分成为实色块。日历保留旧原生子树并由硬件图层交叉淡化，取消同步截图；过渡内合并新请求，视图构建等待视图条惯性与吸附完成。

Dock 松手继承实际屏幕速度，先以每秒 5 的指数阻尼自由运动，边界外用弹簧回拉；减速到每秒 0.08 槽位以下再按当前位置取最近项目。内端达到半个标准宽度越界位置后固定，外端继续随物体位置和宽度弹性延伸，回拉后恢复整体移动。动画关闭时使用指数阻尼的预测落点直接完成选择。主导航收窄、增大左右留白，选中标签和图标使用主题色。

离线与真实浏览器检查已通过，Android 实际帧率和采样效果仍需真机验证。

## 0.14.6 页内动效

原生卡片进入视口时以 8dp/240ms 轻量呈现，错峰最多 90ms。`UiMotion.observeScroll` 幂等绑定、缓存直接子项，通过观察器合帧；不替换页面业务滚动监听。`settleScroll` 用于恢复和后台重绘，内容直接稳定显示。输入、横向区域及当前输入/无障碍焦点不移动，动画关闭或 detach 时清理回调并收敛。

首页/详情页和 Dock 保留原有手势跟随，收尾按剩余距离计时。详情展开收起使用同一高度/透明度进度，反向操作先取消旧完成动作并从当前高度继续。课表仅主动切学期后过渡课程内容，控制区固定、双轴滚动位置保留。公共按钮按压 90ms、恢复 160ms；弹窗仍仅由窗口执行 220ms 进入/160ms 退出，Activity 转场和预测返回交给 Android。

玻璃表面随滚动每帧合并刷新。交叉淡化捕获当前合成画面的可见区域，最长边 1024px、总像素最多 524288（ARGB 上限 2MiB）；替换、失败及 detach 释放旧快照。

LAN 导航按方向短距离进入，Dock 高光连续移动；IntersectionObserver 一次性呈现滚入的卡片。快速反向的弹窗、下拉与展开面板从当前显示帧衔接。运行中开启减少动态效果会完成终态及关闭清理；十秒轮询不播放动画，编辑焦点、选区和滚动恢复保留。旧弹窗请求和关闭回调不能作用于新弹窗，过期路由请求不回写内容或 revision。

验证见 [验证记录](validation-history.md)：离线检查与真实 Edge 模拟手机 API 能检查逻辑和浏览器动画，但尚未验收 Android 真机视觉、帧率或手机端到端。以下为启动优化的历史记录。

## 0.13.76–0.13.78 启动优化历史

本轮启动优化始于 0.13.76；0.13.78 根据设备反馈移除了与系统预测返回衔接不佳的 Activity 自定义转场。目标是首页尽快可用、玻璃控件保持一致、进入和退出有连续过渡。**尚不能确认 1 秒启动、实际帧率或视觉验收。**

## 项目巡检与处理

| 范围 | 发现的问题 | 本轮处理 |
| --- | --- | --- |
| 首页启动 | 壁纸准备时 OnPreDraw 拦截整个窗口，最多等 2500 ms | 删除首帧门闩，主题底色即时绘制；图片与模糊后台准备后同步淡入，模糊失败可显示原图 |
| 首页数据 | 首次恢复在 UI 线程查询数据库、核对历史并重复读取 revision | 首批首页数据与建库/升级在后台准备，一次读取有数量上限的首页数据；首批渲染复用 revision |
| 后台恢复 | 读取完整任务历史后筛选解析中记录 | 只查 processing 的 ID，后台核对；与 job claim 共用锁，条件更新不覆盖刚完成的记录 |
| 权限与更新入口 | 首次内容绘制前触发后续工作 | 首次内容绘制后再进入引导、权限、更新和维护；保留原触发规则 |
| 系统日历 | 每次恢复清空刷新时限；取消结果可能压制重查 | 保留有效缓存，取消/过期/失败结果失效时限；前台重新查询 |
| 引导、设置、备份、更新、弹窗按钮 | 实色主按钮、不同的次按钮背景、禁用态不明显 | 共用 acrylic 表面、主题文字、圆角、ripple、按压反馈与禁用文字颜色 |
| 表单与外观 | 输入框、下拉入口、复选/开关颜色不统一 | 使用公共表面及状态配色；小组件预览时间改用现有玻璃滚轮 |
| 引导步骤 | 正文即时替换 | 仅捕获可见滚动视口做短交叉淡化，固定头尾保持稳定，旋转仍恢复步骤及滚动位置 |
| 所有 Activity | 自定义进出动画与系统预测返回衔接不佳 | 0.13.78 移除 Activity 转场覆盖与资源，由系统完整管理进入、返回提交与取消 |
| 公共弹窗 | 有进入，退出直接消失 | 由窗口管理器统一 220 ms 进入、160 ms 退出，覆盖确认、取消、外部点击与返回 |
| 详情返回 | 总是注册拦截回调，普通浏览失去默认预测返回 | 仅有未保存编辑或正在保存时注册回调 |
| 详情横滑 | 双动画各遍历两棵 View 树；每次 MOVE 更新 | 每显示帧合并 MOVE，收集并复用玻璃控件，单个动画负责每帧刷新 |
| 记录与详情图片 | setImageURI 在 UI 线程解码 | 两个后台工作线程、按显示用途降采样、4 MiB 内存缓存、生命周期身份校验 |
| 局部主题切换 | 无效快照路径也分配 Bitmap | 先验证宿主，取消旧动画、清理旧快照并归一透明度后再捕获 |

Activity 转场完全交给系统管理，不再通过 Application 生命周期覆盖。页内动效和弹窗动画独立保留；Dock 主体切页时仍使用页面/高光共用进度，直接拖动 Dock 则从当前高光位置平滑追随手指。

## 测量与验收

区分 [Android 官方定义的 TTID 与 TTFD](https://developer.android.com/topic/performance/issues/launch-time)：前者是初始显示，后者通过 `reportFullyDrawn()` 报告主要内容已就绪。首页加载提示不报告完成；启用系统日程时等待当前窗口的查询结束与内容绘制。壁纸作为装饰独立加载。

`ChronaStartup` 的 `activity_ms` 只从 Activity 实例计时，不能代替包括进程启动成本的系统 TTFD。系统日志与应用就绪标记都存在时，脚本才判定该样本可用于验收；失败或缺失的样本不会算作达标。脚本不安装、不清数据、不更改引导和权限配置。

先在测试设备安装相同签名的当前版本，结束所有解析工作并完成引导/权限配置。以下命令会强制停止应用进行冷启动，不能用于正在解析真实任务的设备：

```powershell
python checks/measure_startup.py --adb 'F:\Android\Sdk\platform-tools\adb.exe' --serial '设备序列号' --samples 10 --target-ms 1000 --allow-force-stop --output build/startup-device.json
```

分别检查无壁纸/大壁纸、少量/较多历史、系统日程开关、首次安装/普通冷启动、热恢复。报告每次数据、中位数、P90、最大值；全部样本系统 TTFD ≤1000 ms 才表示该设备和条件下本次目标达成。设备性能、系统调度、首次数据库迁移与日历 Provider 耗时仍可能使结果超过目标；不要将一台设备的成绩推广为所有设备保证。

动画验收需覆盖：引导快速连点与旋转、打开/关闭及嵌套弹窗、详情未修改/有修改/保存中返回、Dock 短按/长按/拖动/取消、主体横滑、图片首次显示与返回缓存、暗色/自定义色/壁纸，以及系统动画缩放为 0。Activity 使用 [系统预测返回](https://developer.android.com/guide/navigation/custom-back/predictive-back-gesture)，需分别验收拖动、取消、提交及按钮返回；拦截未保存编辑时以数据保护为先。

普通返回/筛选的数据刷新和部分非首页页面仍沿用同步、有边界的查询；本轮没有改成全应用异步数据架构。实际耗时需要先取得设备剖析结果，再针对仍然超标的路径优化。
