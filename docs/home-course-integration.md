# 首页、课程与可信反馈（0.13.85）

本文件为 0.13.85 的历史实现记录。0.14.4 已取消课程注入：首页/日程/小组件不加载导入课程，HomeCourses 删除，当前行为以 [课表说明](course-timetable.md)、[系统日程开关](system-calendar-home.md) 和 [候选合并](candidate-merge.md) 为准。

本轮按独立模块实施课表/小组件、详情提示、提醒诊断、发布验证、小组件偏好；主线负责首页异步整合、筛选状态、时间参照及验收。保持原有主题、课程聚合网格和系统日历确认流程，数据库仍为 v9。

## 数据与展示

- `CourseAgenda` 输出全部启用学期在时间窗口内的实际安排，涵盖常规与特殊课程。去重忽略描述变化，保留实际时间与来源；不把外部同名日历事件当作相同课程。
- `HomeCourses` 独立后台读取，缓存窗口绑定日期、时区和课表版本；过期结果和销毁后的回调丢弃。课表结果到达后保持首页滚动位置，并等待课程加载结束才报告首页主要内容就绪。
- `HomeTimelineEntry` 保留拾时候选、系统日程、课程三类真实身份，课程点击通过稳定学期 ID 与 occurrence key 定位。
- `TimetableStore` 缓存已解析文档，成功保存、删除、恢复及回滚失效；版本读取不等待文件/解析锁。课表单源故障不隐藏小组件其他来源。
- 日程筛选摘要使用与查询相同的范围规则，包括系统来源隐含的月份；重置清除范围、类别、写入状态、来源与关键词，保留时间标签。

## 可信反馈与时间

相对时间按记录创建时刻固定，解析设备时区沿用现有行为。编辑旧原文后重解析仍采用可见的原参照，既有日程不自动重算。传输超时与语义时间分离。

`CandidateFeedback` 只从已有状态生成短提示；没有字段级原文来源、候选 reason 或逐条链接失败记录时不作推断。普通文件明确仅提供元信息。`CategoryTimeChange` 处理生成时间的类型切换，转为截止时冻结明确截止并清除“默认结束”标记。

提醒诊断只读权限和本地日历状态，查询在后台、离开页面取消/丢弃回调。日历通知设置及真实提醒送达仍由用户在系统日历核对；应用不声称能够从自身通知权限判断系统日历。

## 偏好与验证

独立弹幕开关默认开启，遵循系统动画开关；关闭时保留已有清理流程。系统设置在下次原有刷新生效，不新增常驻服务或轮询。预览时刻和弹幕开关纳入完整备份与失败回滚。

`checks/run_checks.py` 明确列出 quick/full 组，失败返回非零，不安装依赖。统一检查发现旧日程测试残留未实现的 completed 字段/第五标签断言；现按真实四标签模型验证历史保留，独立重新编译当前查询代码，并移除固定 Java 路径。该修正没有更改业务查询或增加完成状态。

新增检查覆盖课程跨学期/全天/跨日/定位/缓存/失败、主线程无锁版本读取、课表故障隔离、真实请求重试参照、筛选摘要、截止转换、小组件偏好和备份语句。文件、网络、Android 生命周期等必要部分使用明确替身，不能代替实机。

release 关闭调试，使用原证书并保留 debug 开发构建；实际 APK 验签与验证结果见 [验证记录](validation-history.md)。设备端操作按 [验收清单](device-acceptance.md) 单独记录。
