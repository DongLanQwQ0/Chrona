# PTA 作业接入：调研与 UI 建议

2026-11-03 · 方案已获批准并实施；实际候选与验收见 `HANDOFF.md`、验证记录。本页保留当时的源码调研与方案依据，现行业务见 `../features/zju/zju-services.md`。

## 结论：可以接入，复用作业链路，单独管理 PTA 登录

Elychron 已有 PTA 登录、读取题集、转换待办与缓存逻辑。建议在 Chrona 增加独立 PTA 数据来源，复用现有作业通知、主页红点、定位、提醒、系统日历和可选 AI 排程；不把 PTA 伪装成「学在浙大」记录，也不增加主导航入口。

调研依据固定源码。实施阶段已用用户提供的会话，在统一模拟器完成真实 PTA 获取与重复同步；没有将 Cookie 写入本页或日志。

## 不照搬的八处问题

1. **同日题集不等于随堂作业。** 上游默认排除本地同一天开始／结束的题集，会漏掉当天发布、当天截止的正常作业。建议不使用这个规则；同步范围允许用户选择题集，可靠分类字段需实测后再用。
2. **题集首次出现考试信息时，ID 可能变化。** 上游 ID 从 `pta:题集ID` 变成 `pta:题集ID:考试ID`。建议以账号与题集 ID 维持稳定身份，考试 ID 作为元数据；若平台确有独立子任务，再按实测结构决定。
3. **机构名不是课程名。** 上游把 `organizationName` 放入课程字段，可能只有「浙江大学」。未可靠关联课程时显示 PTA，不擅自归入 C 语言；允许用户关联课程。
4. **未来列表缺席不等于删除。** 到期、权限变化、网络失败都不能抹掉已入库作业；保留历史和逾期状态。
5. **单题集错误可能掩盖登录过期。** 上游非严格请求先吞 403／404；Chrona 应先识别认证错误，再区分无权限／无考试与整体失败。
6. **只比较 ID 与截止会漏更新。** 标题、正文、链接、平台状态也要纳入实际变更判断；无变化不重复通知。
7. **退出 PTA 不应退出其他网站。** 上游清理 WebView 的全部 Cookie；Chrona 仅处理 PTA 会话，不能破坏学校登录。
8. **完成状态不能猜。** 上游实测未取得原先预期的完成字段；提交、得分、全部通过也不必然同义。真实字段确认前用本地完成状态，不自动覆盖。

上游为 GPL-3.0；建议独立实现接口适配与映射，不直接移植整段 Dart 代码。若引用代码，应先核对许可及分发义务。

## 接入现有业务的边界

- 入口：现有 `ZjuSync`、`ZjuHomeworkStore`、`HomeworkNotice`、`ZjuHomeworkPlanner`、`ZjuHomeworkCalendar`、`HomeworkLinks`。
- 当前管理状态含学在浙大专属单例与来源。实现时按来源／账号隔离同步状态、记录映射、删除抑制与请求代次，不能把 PTA 塞入原学校快照造成互相清理。
- 共用作业落库和通知后处理，避免新增第二套红点、定位、日历与提醒机制。官方截止与用户执行时间分离，用户手动安排不被同步覆盖。
- 登录 PTA 不自动开启 AI。用户启用对应新作业排程后，复用现有排程约束和审计；平台资料发送范围需在启用流程明确。
- 建议首次同步汇总一次，后续仅新作业触发新作业通知；普通刷新不重复提醒。失败保留最近成功内容，账号切换不混合记录。
- PTA 题集仍属于作业来源；不进入只用于教务考试的「考试」类型。不进行提交代码、开始考试等写操作。

## UI 建议：四个位置即可

遵循现有 `ui-style-contract.md`、`ui-interaction-baseline.md` 与 `features/zju/zju-services.md`；以下是布局建议，不是已实现截图。

### 1. 折姜星辰：增加「PTA 作业」入口

放在现有作业同步设置附近，点开二级设置页，行尾仅显示「未登录／已开启／需登录」。PTA 登录与学校登录独立，学校同步关闭时仍可进入 PTA 设置。不添加新的主导航栏选项。

### 2. PTA 作业：紧凑的二级设置页

```text
返回             PTA 作业              刷新

账号                    昵称 · 退出登录
作业同步                            开关
同步题集                       全部  ›
关联课程                             ›
最近同步                 14:20 · 6 项
```

- 未登录时账号行提供「登录」，打开官方登录页面。高级会话导入若确有需要，再放操作菜单，不把 Cookie 输入框铺在主页面。
- 复用 `SettingsPageLayout`：左右 20dp、标题下至少 16dp；单个刷新动作保持圆形。确需多个相关操作时用 `HeaderActionGroup`，不拼按钮样式。
- 字段／选择面板复用现有实现；长题集名自然换行，不能缩字号硬塞。页面整体可滚动，横屏不固定占用大片顶部空间。
- 「同步题集」默认全部可读取题集；用户可排除特定题集。与其猜测随堂类型，不如明确控制范围。列表很多时提供搜索。
- 「关联课程」只在无法可靠得到课程名时需要，不强制首次登录完成关联。

### 3. 日程／首页：继续使用现有作业卡片

```text
C 程序设计基础 · 循环练习             PTA
截止 11月6日 23:59
执行 11月4日 19:00–20:00
```

标题沿用当前实际课程关联；未关联时只用题集标题。来源「PTA」放现有来源位置，不再重复在标题前加前缀。执行时间有值才显示。点击仍进入统一任务详情，平台链接打开对应题集；个人执行时间、提醒与完成操作保持原体验。

来源筛选放现有筛选面板：「全部／学在浙大／PTA」，不增加一排常驻工具栏。作业分类同时包含两个来源。

### 4. 登录过期／同步失败：原位反馈，不打断阅读

- 登录过期：来源设置行显示「需重新登录」及入口，既有作业继续显示；不每轮弹提示或重复发通知。
- 网络失败：保留旧数据，刷新结束恢复按钮；只在同步状态处显示简短错误。
- 登录、设置与选择面板统一进入／退出动画。异步同步不重建整页、不改变滚动偏移；系统减少动画沿用公共处理。

## 实现后应验证的内容

1. 统一模拟器正常登录，验证匿名 Cookie、有效账号、过期、退出与换账号；不破坏学校登录。
2. 比对真实题集列表、分页、个人截止及北京时间；覆盖同日作业、无考试对象、过期题集和无权限题集。
3. 重复同步不重复建任务；题集增加考试信息、改标题／截止后仍更新原记录；失败不清空，手动安排与删除抑制保留。
4. 新作业走原通知／红点／定位路径，AI 仅按用户启用状态运行，审计关联正确。
5. 正常竖屏／横屏核对内容高度、长名称、深浅主题、操作组高光及开合动画；遵循公共运动包络，不新增一套视觉语言。

方案落地的具体位置、真实接口与测试证据进入验证记录，不以早期调研中的待验证项覆盖当前结果。
