# AI 解析链路

时间与分类规则见[AI 时间提取约定](ai-time-extraction.md)，服务能力与参数见[请求协议](ai-request-notes.md)。提示词版本由 `SchedulePrompt.VERSION` 管理，当前为 `schedule-v17`。

## 从输入到日历

记录／分享 → `ProcessingJobService` 收集原文、图片、链接正文及文件元信息 → `ChatCompletionClient` 请求 → `SemanticEventNormalizer` 转换时间 → `CandidateRules` 校验 → `TaskStore` 保存 → `AutoCalendarPublisher` 自动写入明确项，或用户审核后写入 `CalendarStore`。

活动、待办、作业按事项含义分类，提醒是属性；执行时段与独立截止分开。纯信息保留在收件原文；输出仅含 `events`，不再生成独立记录。模型提取语义，程序处理时区、时间换算、全天边界、默认值及合法性。合理推断给出具体建议并标存疑，不因反复比较可能性拖延输出。

同一未来事项的多个子项由模型用 `plan_group` 标识并按依赖顺序输出，`plan_until` 提供总截止或活动开始这一准备边界。`SemanticEventNormalizer.fromJsonBatch` 在整个可用周期内分散执行建议，固定执行时间分隔前后阶段；不把分组子项压回截止前最后三天。分组随本轮解析审计保留，不新增业务父子层级，也不重排已经保存的日程。

明确且无需确认的有效项逐项自动写入；缺少信息、权限或写入失败时保留草稿及原因。混合批次只处理可写部分，关联失败补偿本次新建，已有关联不重复创建。审核状态、完成状态与系统日历关联分别管理。

已确认日程自动清理通知栏的解析结果通知，原始收件、日程和审计保留。收件READY且本批非空事项全部settled后清理；还有待处理项的混合批次、失败、处理中和空结果保留。自动确认完成时不再发一条无须处理的结果通知；手工、网页和批量确认后的数据刷新复用后台更新入口清理已有通知，不依赖提醒总开关，不影响解析进行中、原子岛、作业或其它频道。

仍需处理的结果通知第一行直接显示事项名称；有已写入项时优先显示已写入日程的名称，多项附数量。收起正文显示状态、标题、时间、地点、提醒及备注，展开后显示处理结果与完整详情。最多列出12项，每项备注最多240字符，更多事项可点击查看；没有事项时显示处理结果。通知权限和系统折叠高度仍由Android管理，点击及「查看日程」进入对应收件详情。

## 固定参照与请求边界

首次解析、重试和重新解析使用 `TaskRecord.createdAtMillis` 作为同一语义参照，按解析设备当前时区解释。排队跨日不改变“明天”；修改旧原文也保留参照，需要以当前时刻表达时新建记录。

重新解析由 `CaptureReparser` 统一校验及清理：自动移除这条收件独占的旧系统日程，保留共享引用、原输入和历史审计；候选替换及排队状态提交后才调度新请求。清理失败不开始解析，调度失败标为可重试的失败状态。跨存储删除及保留规则见[系统日历关联](../schedules/schedule-browser.md#系统日历关联)。

静态规则与 schema 保持版本化前缀，动态内容以 JSON 随后提交；图片保留多模态内容。原文上限 24000 字符，链接正文 4000，普通文件元信息 6000；后两者截断带标记。文件元信息不等于文件正文。外部内容作为待处理资料，不成为系统指令。

网络工作共用 240 秒预算，取消断开当前连接。仅网络、限流和临时服务故障允许网络重试；完整响应结构错误或截断不自动再次付费请求。服务拒绝已选思考参数时报告错误，不静默取消用户选择。

## 输出与可观测结果

每项的七个时间依据字段由 `TimeAssessment` 校验，并与本地实际时间、字段存疑及转换原因分别保存。`ProcessingJobService` 为每次请求尝试创建 `parse_runs`，成功候选及 `parse_time_entries` 同事务提交；输入、偏好和请求快照不含连接密钥。失败、取消和进程中断各留状态，重解析不覆盖旧依据。普通诊断日志只记对应 `runId`，完整审计通过已认证的局域网 `/api/parse-audit` 分页查询。字段及关联语义见[时间依据](ai-time-extraction.md#确定与存疑的依据随解析留存)。

预览读取答案；完整输出保留服务实际返回的思考与答案，思考空格及换行原样保留，仅格式化答案 JSON，再分页。完整输出格式化在独立线程执行，最大约 8MB；预览保存失败不重复调用模型。

思考强度作为非敏感配置参与备份。服务启用内部推理与返回可见推理文本是两个独立结果；没有返回时不伪造文本。缓存命中和 token 数只采用服务 usage，缺失保持未知。

## 验证入口

浙大新作业的可选排程由`ZjuHomeworkPlanner`串行处理：入库事务保存专用队列，正式学校同步与通知完成后至多处理一项，复用`ChatCompletionClient`与相同时间转换器。它不替换官方候选，成功时同事务更新执行起止与关联审计。开关显式授权直接应用，模型仍保留真实存疑；网络期间不持同步锁，提交时核对个人编辑／完成／删除、账号与官方快照。`checks/zju_homework_planner_check.py`使用真实SQLite和fake provider，不调用真实AI。

请求契约使用 `checks/AiRequestCheck.java`，自动写入使用 `checks/ai_auto_publish_check.py`；时间语义入口见时间提取约定。它们不调用真实模型。各版实际执行结果见[验证记录](../../validation-history.md)，真实语义准确率、推理文本与缓存命中需独立服务证据。

重新解析的设备检查为 `CaptureReparserInstrumentation`，通过 `checks/reparse-validation.init.gradle` 构建隔离测试包，校验真实SQLite和日历provider且不发AI请求；网页交互运行 `node checks/reparse_web_check.cjs`，使用已安装Edge及明确标记的模拟手机响应。
