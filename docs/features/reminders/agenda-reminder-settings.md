# 日程来源与提前提醒设置

## 离开应用后保持更新

有原子提醒正在显示时，Chrona 启动本地前台更新服务，按分钟及开始/结束边界更新卡片；开启秒显示时，复用其中的秒级链路更新展开倒计时。屏幕点亮或解锁时立即刷新。最后一条原子提醒结束、隐藏、完成或关闭总开关后，服务停止。服务不联网、不持有唤醒锁，普通提醒不启动它。原有边界闹钟仍保留。

设置 → 日程常驻提醒 → 后台运行可打开本应用的系统设置。vivo 需选择“电量 → 后台耗电管理 → 允许后台耗电”；真机检查发现“智能控制后台耗电”会冻结进程并延后闹钟，即使前台服务已经运行。仅调整 Chrona，不需要修改其它应用。前台服务在系统通知区显示静默的“日程提醒正在更新”。

Android 前台服务使用声明了用途的 `specialUse` 类型；系统拒绝启动时记录日志，既有闹钟继续调度。见 [前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types)及[后台启动限制](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)。

Chrona 活动若配置了超过 30 分钟的提前提醒，原子通知从该提醒时间开始出现，例如提前 120 分钟则提前两小时展示；其它日程以及未设置更早提醒的活动仍提前 30 分钟。此规则仍受提醒总开关、来源开关、最多三条及本次完成/隐藏控制。查询分别获取已经开始、已经进入提醒窗口和下一提醒边界，避免更早提醒的远期活动被未到提醒时间的近期活动排除。

“日程常驻提醒”中的“原子通知使用壁纸”默认开启，使用外观中当前启用的 Chrona 壁纸，生成小尺寸 Gaussian 模糊背景并叠加主题色遮罩。关闭此开关时使用流动极光；未配置或无法读取壁纸时也使用极光。此开关独立于日程来源和提醒总开关，修改后更新已有通知。背景动画由系统宿主播放，不新增逐帧通知或解码。

设置中的“系统日程”入口汇总首页与日历页的显示开关。原页面开关保留，共用各自的偏好；日历沿用原 Activity 的同名偏好文件与 system 键，不复制或迁移状态。首页、日历、小组件、提前提醒的系统来源彼此独立。

提前提醒按以下顺序决策：

1. “开始前30分钟提醒”关闭：不发送，结束已有提醒并取消下一次闹钟。
2. 系统来源且“提醒包含系统其他日程”关闭：不读取、不提醒，也不进入原子通知。它优先于系统日程原子通知开关。
3. vivo、自有场景已启用、系统通知权限允许，且该来源的原子通知开关开启：使用原子通知。Chrona与系统来源分别选择。
4. 其余已允许提醒的日程使用普通常驻提醒；系统通知权限未允许时不发送。

原子选项默认开启以保留既有提醒方式。不可用、总开关关闭或系统来源被禁止时，相应原子选项禁用，但保留其选择。通知权限、场景能力在后台读取，界面返回及通知授权后重新检查。切换通知形式时，先结束并取消旧卡片，再用同一槽位发送新卡片，避免关闭原子选项后残留原子岛。

页面布局统一遵循 [UI 规范](../../ui-style-contract.md)。

胶囊在开始前最后两分钟显示系统秒级倒计时；活动结束前也采用同样显示。非活动日程开始后保留“已开始”最多三分钟，然后关闭并从提醒候选中排除，实际日程的结束时间不延长此提醒窗口。活动继续进度直至结束。分钟级刷新按固定过期时间重新计算超时，不会从刷新时刻重新计三分钟。

展开卡片在开启秒显示时，全程显示分、秒，超过一小时带小时；活动开始前倒计至开始，进行中倒计至结束。复用现有前台服务的秒更新和固定模板快照，原子胶囊仍仅最后两分钟切为秒数；不重查日历、不增加权限或网络请求、不延长胶囊详细展示期限。关闭秒显示恢复原分钟文字，已结束／待完成／已逾期保留状态；刷新延迟时保留上次非负文字，不运行可能越过零后变负的宿主计时器。

新增学校作业使用独立的十分钟信息通知，复用已注册的 vivo 原子岛推送协议。它采用作业专用卡片，显示作业信息与关闭「×」，不带地点、日程进度或完成操作；关闭不修改作业。该通知不启动日程倒计时服务，不占用日程提醒槽位；详情与同步频率见[折姜星辰](../zju/zju-services.md)。
