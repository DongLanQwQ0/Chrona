# 多设备 WebDAV 同步协议

本文件描述多台 Android 手机共同使用的 v1 数据格式。同步内容为记录原文、日程、附件、课表学期及已完成课堂总结；AI/WebDAV 密钥、界面偏好、设备日历事件 ID、提醒设置和处理队列留在本机。局域网浏览器调用所连接手机的 API，共用手机数据与同步身份。

已完成课堂总结使用 `classroom_<UUID>`，UUID 由课程与回放编号确定。payload 为 `kind: classroom`、`document`（总结 Markdown 与完整字幕）及 `attachments`（正文引用 JPEG 的内容寻址清单）。复用版本向量、多值冲突和附件传输；未完成或正在处理的课堂不覆盖，缺少本机缓存不表示删除。此格式需要所有同步设备更新至支持课堂文档的版本。远程截图 URL、账号凭据与 AI 生成检查点留在本机。

## 记录

对象 ID 为 `task_<UUID>`、`term_<学年>_<季节编号>`、`classroom_<UUID>` 或 `merge_<source candidate UUID>`。task/term/classroom 使用版本向量和多值寄存器；并发修改保留全部版本，用户选择后产生一个覆盖已知版本的新版本。task/term 的删除使用有版本的墓碑，不以云端文件缺失判断删除；classroom 不支持同步删除。0.14.4 的 merge 为不可删除的单调记录，较小目标 UUID 优先，版本向量合并，详情及验证见 [合并日程](../schedules/candidate-merge.md)；所有同步设备需升级到 0.14.4 或更新版本。

任务 payload：

```json
{"kind":"task","rawText":"原文","source":"manual","createdAt":0,"status":"ready","linkText":"","candidates":[{"id":"UUID","title":"事项","startAt":null,"endAt":null,"zone":"Asia/Shanghai","location":"","description":"","category":"event","allDay":false,"endAutoGenerated":false,"uncertainty":0}],"attachments":[{"sha":"64位小写SHA256","name":"文件名","mime":"image/jpeg","size":0,"image":true}]}
```

任务状态只同步 `ready`、`needs_review`、`failed`；正在处理的本机任务等处理结束后才参与同步。候选 ID 跨设备稳定；本机提醒及日历关联按该 ID 保存。附件内容按 SHA-256 寻址，单个附件上限 20 MiB。

学期 payload：`{"kind":"term","index":0,"document":{...}}`。document 与现有 TimetableStore 编码相同，含 format/name/ics/importedAt/zone/plan/enabled/classification；enabled 仅含该学期 index。每个学期单独合并，选择中的学期不跨设备。原始 ICS 与学期边界保留。

## 传输与故障处理

Android 协调器保留单 worker 和运行中互斥；数据库捕获、重新捕获及应用各自在同步锁内完成。HTTP 交换期间释放同步锁并关闭数据库句柄，局域网页面可继续读取；应用前重新读取并捕获本机修改，再合并网络结果。确认冲突全程持锁，测试连接在锁外执行，设置保存持锁。

备份恢复递增恢复代次。网络期间发生恢复时，旧交换结果丢弃，不打开旧数据库、不回写旧合并结果，也不覆盖恢复状态提示。同步附件缓存为独立的 `sync-blobs` 内容寻址目录，恢复不会替换或清理该目录；传输期间可继续使用缓存文件。

WebDAV 根目录为用户配置地址下的 `ChronaSync/v1`。`heads/<device UUID>.json` 为该设备已知的完整寄存器集合；`blobs/<sha>` 为不可变附件。每台设备拥有独立身份，进程内协调器串行发布，只写自己的 head，不覆盖其他设备 head；备份恢复时更换设备身份。每个 head 最大 32 MiB。

列表只用于发现文件，不要求列表提供 ETag。先读取并验证全部 head，上传必要附件，再发布自己的完整 head。GET 提供强 ETag 时用 `If-Match` 防止版本变化；文件尚不存在时用 `If-None-Match:*` 创建。既有文件没有强 ETag 时，由独立设备身份和串行单写者保证写入范围，更新自己已有的 head，不误当作新文件。缺失、弱 ETag 及未带引号的非标准标签均不作为有效条件标签；不编造标签，也不将无效标签传入 `If-Match`。失败不清空本地记录，不删除云端数据。

合并审计 `merge_` 与普通任务、学期共同通过交换层验证，仍检查身份、目标递减关系及完整来源快照。网络、认证、权限、限流和条件冲突显示固定的具体原因与 HTTP 状态，不输出服务返回正文、账号、地址或凭据。

先下载并校验所有 head，再合并；下载所需附件并校验 SHA-256 后才应用本地。并发版本暂不替换本机正在使用的记录，交由冲突界面选择。Android 日历绑定记录遇到远端修改/删除时要求在手机上确认处理，禁止因同步直接创建、修改或删除系统日历事件。

Android 完整备份恢复时，在同一同步互斥锁内清除设备 head ID、关闭自动同步。DB10 备份保留实体映射/合并标记，恢复先固化现存未映射实体，再轮换未来新实体的命名空间，保留已有实体 UUID；避免 sqlite_sequence 回退造成身份重用。task 应用基线清空，恢复内容与云端不同的版本可能待确认。正常离线重连保留身份与墓碑，不执行此重置。
