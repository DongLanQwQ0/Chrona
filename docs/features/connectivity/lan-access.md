# 局域网浏览器访问

网页是手机的轻量远程入口，主导航仅保留首页、日程、收件箱，以及普通记录详情、编辑和采集。课堂、课表管理、完整日历、来源管理、同步冲突、合并和高级设置继续在手机操作。首页和系统日程列表仍可读取手机已启用的课表及日历来源，不在网页另建配置。主题跟随手机，不提供独立深浅色覆盖。

## 日常操作

| 页面 | 操作 |
| --- | --- |
| 首页 | 下一件事、待办摘要、未来时间线、待确认与失败计数；作业快捷入口与系统日程开关共用标题操作组 |
| 日程 | 待处理／待安排／历史／全部；类型、日历状态、待办范围和日期预设筛选；搜索、排序、分页、跨页选择、批量写入与删除 |
| 收件箱 | 状态与类型筛选、排序、搜索、分页、跨页选择、批量写入与删除 |
| 详情 | 完整日程正文、普通记录原文与附件；重新处理、追加事项、编辑、删除与写入；待办／作业完成和恢复；有效活动确认及撤销 |
| 作业详情 | 来源管理的标题、内容、截止时间与类型只读；执行时间和提醒可调整，可清空执行时间；来源提供完整链接且折姜星辰启用时显示直达按钮 |
| 采集与附件 | 「＋」仅首页显示；文字、图片和文件先保存，再逐一上传，全部成功后按用户选择调用 AI；已有普通记录可追加附件 |

筛选选择栏共用网页组件与主题色，选中状态具有无障碍语义；同组宽度由内容区域统一分配，高光位置与宽度连续过渡。完整标签放不下时原位显示当前值，打开共用选择面板，不缩小字号。标题与图标动作同行，搜索、筛选、计数与首条记录之间仅保留一份必要间距；横屏保持整页共同滚动，工具随阅读退出。

普通模式不常驻复选框。计数行「选择」或记录长按进入批量模式，以圈勾表达选择；计数行保持同高，提供本页、全部筛选结果、写入、删除及取消。选择跨分页保留；更改筛选或切换首页／日程／收件箱时清空，同一主页面进入详情再返回保留选择、筛选、页码与滚动位置。常规短横屏将既有标题／排序与搜索同行、筛选摘要与计数同行，标题行保持48px，正文仍随整页滚动；普通竖屏保留原有纵向结构。

每十秒自动刷新三个主页面，保留搜索输入节点、未提交文字、光标、焦点、筛选控件及滚动偏移；过期的异步筛选结果不能覆盖新筛选。编辑、附件操作、选择面板及浮层期间暂停轮询。局部刷新复用内容未变的首页节点，用位置过渡呈现布局变化，不重播页面入场或重建底部 Dock。用户前后翻页时仅结果区按方向退出、进入，搜索与导航保留实例；系统减少动画时直接切换。
首页的时间线、下一件事和待办分别使用独立的展示节点标识；同一日程在多处出现时，各区域保留自己的节点。每轮刷新每个旧节点最多复用一次，不跨区域搬走记录；十秒自动刷新与手动刷新遵循同一规则。

首页作业入口强制进入「全部＋作业＋未完成＋最早优先」。有未读红点时，通过`/api/schedule?locate=<candidateId>`在当前筛选内定位手机给出的真实分页，将目标行居中并短暂主题色强调；仅在文档可见且目标行实际完成布局并可见后调用`/api/homework/seen`，只清当前目标，不因点击入口或打开详情清除。未匹配筛选的目标不定位。

作业页刷新调用`POST /api/homework/refresh`异步提交；接受后显示忙态，轮询`session.homeworkRefreshing`结束后刷新当前内容并显示手机结果。`homeworkRefreshAvailable=false`时显示手机提供的真实无法刷新原因，学校登录及配置仍在手机管理。

记录详情采用主从布局：桌面约30%紧凑列表与70%完整详情；窄屏在列表和详情之间切换。列表仅展示标题、可用的课程名、时间和状态，未完成项按最近截止（无截止取执行开始）优先，同时间按稳定ID排列，未定时间放在未完成分组末尾，已完成项后置。选中状态同时使用主题边线、底色及无障碍语义；逾期、临近截止与完成使用对应状态文字、图标和主题配色。不从标题猜测课程名，来源未提供时不保留空标签。

详情仅挂载当前项，正文完整展示、随页面滚动，无卡片内滚动、横向切换或底部事项下拉。外部入口按candidate_id直接选择目标，列表中保证该行可见；点击列表或使用上下方向键、Home/End切换后更新可刷新的身份。刷新与返回保留当前项、列表及页面位置。底部仅保留主导航，编辑操作位于详情顶部。

「修改」在详情区原位展开共用表单，按基础信息、时间与地点、备注分组；备注至少120px且可纵向调整，执行时间旁保留清空操作。保存／取消吸附在Dock上方，窄屏和大字体自然换行，弹窗调用时操作区固定在弹窗底部。编辑期间刷新不替换草稿，离开或取消有未保存内容时须确认；保存期间锁定字段及相关操作，失败保留草稿、就地报错，重试仍使用初始revision避免覆盖并发更新。

普通记录原文、链接正文、附件与记录操作收纳到「原始内容」浮层；学校托管作业不显示该入口。编辑、重复、完成及来源直达继续操作当前项。公共弹窗只在按下和松开均位于真正遮罩时关闭，内部空白及从内部拖到外部不关闭，关闭按钮至少48px。

批量写入调用手机的 `BulkCalendarPublisher`：收件箱提交 capture ID，日程页提交 candidate ID；每条独立提交，信息不完整、已完成、已关联或正在处理的事项跳过，并返回写入／跳过／失败数量。旧 revision 在执行前拒绝。选中范围可跨分页保留，每次最多 500 条；更改筛选会清空所选。完成控件固定48px圆形热区：普通待办用时钟，逾期待办用提醒时钟，完成后用勾；活动确认与待办完成调用各自接口。待确认活动卡片不显示有效活动确认按钮，详情仍遵循原有业务合同。

## 与手机端的范围差异

日程排序按标签分别保留，筛选支持今日、本周、本月及前后一段；待办范围与类型联动。重复日程共用手机规则与操作入口，可查看月份实例、设置新系列、跳过、改期、单次完成/恢复和停止；停止保留历史，详见[重复日程](../schedules/repeat-schedules.md)。

浏览器通过在线手机工作，没有独立云端数据库。AI 与 WebDAV 凭据、折姜星辰登录、备份恢复、来源配置及课程关联在手机设置管理。时间刻度缩放与系统级提醒配置保留在手机端。

附件每个最多 20 MiB，逐个流式上传；失败时保留已保存原文与成功附件，重试只发送未成功项目；版本冲突后的下一次重试先读取最新记录版本，不自动重传。纯附件记录使用类型占位原文，不将文件名作为正文。图片复用手机图片导入和 AI 处理；普通文件沿用元信息提取，不把文件名视为正文。学校管理的作业收件及正在处理的记录不能追加附件。上传、来源修改和同步冲突操作同样要求已配对会话与 CSRF 凭证。

列表日期按当前查询范围分组，保留后端排序：逾期筛选取`overdueAt`，今日截止或查询类型为作业时取`effectiveDue`，其它取执行开始／开始／截止。全部类型中的作业仍按执行日期分组，不因单项类型改用截止日期。截止范围取手机`session.zone`日期；默认范围中本地候选按`executionAllDay`决定是否取UTC自然日期，待办和具有截止时间的候选也遵循此规则。收件箱取创建时间。外部系统实例已由手机投影为显示时间，全天日期始终取手机时区，结束日期取exclusive end前1ms，不能再次按UTC解释。收件审核状态共用`TaskStore.reviewStatus`，明确但尚未写入的活动仍进入待确认。

外部活动使用精确十进制字符串`externalId`与显示开始时间调用`POST /api/agenda/acknowledge`；服务端重新解析当前启用来源的实例及真实结束时间。前端不使用可能损失精度的数字ID写入，不改动系统原事件。确认状态具有独立`acknowledgementRevision`，数据库revision未变时仍刷新。

## 结构与数据边界

### 通过 GlobalSend 发送访问地址

局域网会话已开启且已安装GlobalSend时，设置页在「可通过手机确认/扫码/配对码授权」提示下方显示「发送到设备」，标题右侧共用操作组刷新设备。设备文字左右内距16dp，沿用设置卡片内容轴。未安装时不占位；已安装但不支持接口时提示更新。设备按稳定deviceId复用行，名字、在线状态与能力更新不重建未变项或打断焦点；只增删变化的设备。页面仍整页滚动，横屏不新增固定工具区。

本机使用显式`dev.globalsend.globalsend/.IntegrationService`、Messenger ABI v1；不读取GlobalSend凭据或缓存，不开放额外HTTP服务。首次点击关联，在GlobalSend确认读取本组设备和发送所选网页；其后在Chrona直接点设备。授权由GlobalSend以系统调用身份与安装签名维护，撤销或安装身份变化需重新关联。未授权不显示组设备；旧版、离线或不支持接收打开意图的设备不伪装为可用。

只有点击目标设备才发送`LanAccessService.url()`的当前实际普通地址，不包含配对码、Cookie或其它授权；设备列表、刷新、页面恢复均不发送。目标范围沿用GlobalSend当前组和sendable条件，接收端须支持`openUrlIntentV1`。首次网页访问继续在手机确认，GlobalSend关联不批准网页配对。LAN关闭或网络变化停止本页连接及查询，不重发旧链接、不拼接其它网卡地址。

一条发送使用一个UUID与120秒期限，状态查询保留这个UUID；每次Messenger RPC另用递增arg1匹配回复，同时核对系统发送UID和JSON requestId，迟到旧RPC不覆盖当前请求。重复点击、重建及未知结果恢复只查询，不自动重发。页面前台查询状态，后台暂停查询但不取消已发送意图；跨重建保留当前请求，超时或未知仍可刷新查询。等待期限结束后即使无新回执，设备操作也恢复可达。

「已请求打开浏览器」只表示目标系统接受启动；「已送达」与「请在目标设备点击通知打开」分别保留真实含义，不当作网页已加载或配对成功。Windows复用系统默认浏览器入口；Android后台受限时由GlobalSend以通知承接。普通文本／链接消息不自动打开，重复／过期意图由GlobalSend处理。GlobalSend传输可达不证明浏览器能访问本机8765，网页仍需要目标设备到当前LAN地址的真实网络通路。

协议由GlobalSend项目的`docs/INTEGRATION_ABI_V1.md`维护，Chrona实现入口为`GlobalSendLink`及`LanSettingsActivity`。隔离Android协议检查使用`checks/global-send-validation.init.gradle`与`src/globalSend`；它的本地假Messenger仅验证客户端，不代表真实设备已互通。实际跨应用绑定、关联、定向接收和浏览器打开须单独留设备证据。

手机设置页的访问链接在配对卡片中居中显示，点击沿用公共按压放大与填充高光，复制成功后以公共反馈显示「已复制」。复制普通URL，不带配对码。未开启或会话已关闭时不复制占位文字，网络变化后使用新会话地址；原长按选择文字保留。轮询不重复设置未变地址，不打断文字选择。

手机是数据和行为的权威。`LanSettingsActivity` 由用户开启会话，`LanAccessService` 使用 Android `connectedDevice` 前台服务监听当前非 VPN Wi-Fi/以太网的私有 IPv4，固定端口 8765；监听失败会如实显示。服务默认关闭，未持久化开启状态，不接收开机启动，也不使用粘性重启。网络地址变化自动关闭，需再次手动开启。

NanoHTTPD 2.3.1 负责 HTTP 解析与 Socket 生命周期，最多 8 个连接，读取超时 10 秒。`LanWebServer` 提供随 APK 打包的 HTML/CSS/JavaScript 和接口。网页复用手机主题色、玻璃卡片、中文页面层级与 Lucide 图标，宽屏呈两栏，移动宽度保留底部导航。网页只有临时界面状态，数据来自所连接手机。

记录/日程经 `TaskStore` 读写，SQLite 事务和 revision 检查拒绝旧页面覆盖；日历通过 `CalendarStore` 操作。普通附件按真实记录关联的文件 ID 读取，图片通过 `ImageStore` 校验的存储名称读取，输入文件路径无法访问任意文件。普通文件作为下载返回，图片以 JPEG 显示。

日历写入共用 `LinkedCalendarEvents` 的引用保护：修改共用事件只拆分当前项，删除保留未选中引用；单条发布与拆分的新事件仅在外层 SQLite 提交成功后保留。具体边界见[系统日历关联](../schedules/schedule-browser.md#系统日历关联)。

已开启自动 WebDAV 同步时，浏览器写入请求 `AndroidSync` 和 `SyncJobService`；SQLite 提交后刷新小组件。手机后台收到的 AI 请求使用普通持久化任务，避免从后台申请仅限前台用户发起的 UIDT；后台限制仍由 Android 决定。正在处理的记录禁止编辑；普通记录重处理共用手机`CaptureReparser`，不在网页另设旧禁用规则。

权限、通知、后台限制、同步冲突与 AI/WebDAV 账号在手机设置管理。系统日历授权无法通过浏览器授予；API 不返回密钥或 WebDAV 凭据。

## 访问保护

- 普通地址首次打开自动申请手机确认，网页显示四位核对码；前台手机打开非导出的原生授权页，在后台通过普通高优先级通知进入，锁屏时须先解锁。只有手机「允许访问」才发放会话；拒绝、网页取消、返回键退出授权页或两分钟过期均不授权。无后台强制弹窗或全屏通知权限。
- 每个申请使用独立 256 位随机标识并绑定来源地址，仅保存在内存；同来源最多一个待确认请求，全局最多八个。申请沿用配对限流；轮询与取消须同源、同来源，批准仅可领取一次。服务关闭或网络变化清空所有请求与会话。手输配对码及二维码仍可直接配对。
- 每次开启生成安全随机六位十进制配对码（保留前导零、10 分钟有效）及独立 256 位会话/写入凭证，保存在内存；配对码通过 POST JSON 提交，会话使用 HttpOnly、SameSite=Strict 的会话 Cookie，写入凭证使用请求头。凭证不放 URL、日志或持久化网页存储。
- Host 必须等于正在监听的 IP:端口，Origin 必须同源；存在 Sec-Fetch-Site 时只允许 same-origin/none。所有非公开接口及附件在读取存储前验证会话。所有修改仅允许 POST，并要求 Origin 与写入凭证，拒绝跨站请求与域名重绑定。
- 配对及授权申请每个来源一分钟合计最多 5 次、全局一分钟最多 20 次，最多 16 个会话；会话 12 小时后失效，配对码过期不影响已建立会话，也不影响手机确认流程。关闭服务清空所有凭证、关闭 Socket。
- JSON 请求最大 1 MiB，配对请求最大 256 字节；二进制附件仅通过专用接口限长流式接收。拒绝未知方法、分块请求体、错误 MIME、无效 UTF-8、超范围/非整数数值和缺失必需字段。静态文件白名单、内容类型限制及 CSP 阻止用户文本成为可执行 HTML。

HTTP 仅适合可信局域网。Android 16/target36 默认允许 INTERNET 应用访问局域网，本实现同时声明/请求附近设备权限以覆盖 Android 16 可选限制。未来提升到 target37 时应按新的 ACCESS_LOCAL_NETWORK 规则调整；当前 target36 不声明该权限。官方说明：[本地网络权限](https://developer.android.com/privacy-and-security/local-network-permission)、[前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types)、[NanoHTTPD](https://github.com/NanoHttpd/nanohttpd)。

二维码由本地 ZXing core 3.5.3 生成，访问 URL 的 **fragment** 携带当前六位配对码（形如 `/#pair=000007`，此处为测试码）。扫码打开后网页最先读取并立即用 `history.replaceState` 清除 fragment，再仅尝试一次现有 `/api/pair` POST；片段不会随 HTTP 请求或 Referer 发送。成功仍取得独立高熵会话，错误/过期/无效二维码回到手动入口，不自动重试、不写持久存储。普通可复制地址不带配对码。二维码须视作临时配对凭据，仅向可信设备展示；10 分钟过期、关闭/重新配对/网络变化的既有撤销机制保留。地址或码变化重绘，过期/关闭清除图像。

二维码承载为 172dp 主题描边圆角白底，8dp 内距，实际码图 156dp；保持黑白对比与四模块静区，不裁切有效码。真实解码、前导零 fragment、码/地址变化、过期及停服由`python checks/lan_qr_check.py`覆盖；本轮`node checks/lan_daily_workspace_check.cjs`验证浏览器前导零配对码只提交一次且先清理URL。授权请求、取消与迟到响应另由`python checks/lan_approval_flow_check.py`检查。

网页图标使用标准 Lucide，连接／刷新／断开在轻量标题行，首页作业和系统日程开关共用操作组。主要路由切换、弹窗进出、链接正文展开收起和反馈使用 120–180ms 可取消动画；列表/按钮保留轻量交互反馈。普通刷新不重播页面动画，快速重复操作以最后一次为准；`prefers-reduced-motion` 关闭这些动画。浏览器检查覆盖触发/结束、快速路由/弹窗/展开切换、输入焦点和草稿保持、桌面/移动与浅/深主题。
