# 备份包含哪些内容

需要保留作业、课表和历史时，使用「完整数据备份」；仅复制外观和服务偏好时，使用「配置备份」。

| 内容 | 配置备份 | 完整数据备份 |
| --- | --- | --- |
| 主题、背景及已有服务设置 | 包含 | 包含 |
| 提醒总开关、系统提醒、原子岛来源开关、壁纸背景、胶囊倒计时与秒数 | 包含 | 包含 |
| 首页待办展开、日历系统来源开关、周图片附带日程索引 | 包含 | 包含 |
| 收件、日程、完成状态、原文及附件 | 不包含 | 包含 |
| 每次AI时间解析的依据、方案关联、偏好快照及状态 | 不包含 | 包含；恢复时将进行中的解析日志标为中断，不改已成功记录 |
| 导入课表、来源选择、课程关联及校历配置 | 不包含 | 包含 |
| 作业远端映射、忽略标记、更新历史与统一收件绑定 | 不包含 | 包含 |
| 学校课表缓存及课程备注 | 不包含 | 包含 |
| 已完成课堂总结、完整字幕及引用图片 | 不包含 | 包含；支持恢复后阅读与 Markdown ZIP 导出 |
| 课堂原始下载缓存与 AI 生成检查点 | 不包含 | 不包含 |

学校绑定只保存随机标识及其匿名映射，不导出学号、密码、Cookie 或登录会话。恢复完整备份后学校自动同步保持关闭；检查账号与来源后再开启。同一账号重新登录可继续使用原作业收件绑定。

提醒的临时槽位、当前通知、延后计时及运行中的服务不复制。恢复时清理提醒运行状态，保留已恢复的静态外观开关，再按日程重新建立提醒。

系统日历 ID 属于当前设备，换设备后需要重新核对来源开关和日历关联。备份不是系统日历服务自身的数据导出。

课表手动写入不新增本地开关或账号数据：完整备份继续包含原始导入课表与学校缓存；生成的系统日历副本由系统日历服务保存，不复制其设备 ID。恢复后可重新手动写入，按目标设备实际日历去重。作业只读边界来自已有远端映射／提交快照，同样随完整数据备份保留。

完整数据备份在同一 SQLite 事务内按列名复制全部业务表、修订号及自增序列，历史升级造成的物理列序差异不影响字段对应。已删除记录的 ID 高水位随备份保留，恢复后的新记录继续使用更大的 ID。

恢复前校验配置和学校数据结构。数据库、配置、解析结果和课堂内容安装完成前失败，使用保留的副本回滚；回滚副本缺失时保留当前数据库并报告恢复失败。安装提交后才清理旧副本、重建提醒和安排课堂清理；这些收尾操作失败时显示具体警告，已经恢复的数据保持不变。

在线数据库句柄与解析执行持有使用租约，解析收到停止通知后也要等实际退出才释放。恢复在既有同步／课堂锁内尝试独占；仍有使用者时立即提示稍后恢复，不取消正在进行的解析。独占持续到安装或回滚、同步身份重置结束；期间新解析延后，普通数据库访问等待完成后再打开，离线快照不占在线租约。只取消待运行的解析作业，其它周期任务保留。

备份清单上限为 40 MiB，单份课堂正文为 16 MiB，均按 UTF-8 字节计算。导出与导入使用相同限制；超过上限时导出报错，不将不符合该限制的包写到用户选择的文件。合法的较长字幕不再受隐藏的 4 MiB 读取上限影响。

离线回归使用合成内容的真实 SQLite 数据库，执行生产代码的 v1→当前版本升级、快照与隔离目录恢复，逐表逐字段核对非默认值，并检查约束、外键、ID 高水位和并发事务快照。`backup_restore_check.py` 另执行生产恢复控制流与文件操作，覆盖提交前后故障、缺失回滚副本和 JSON 容量边界；其 Android／SQLite 边界使用替身。

隔离 Android 模拟器已通过完整 `write → prepare → restore`：真实 SQLite 和 ZIP、超过 4 MiB 的中文课堂字幕、收件与解析输出，以及提交后清理调度失败时的数据保留。该测试未使用真实账号，也不覆盖本轮未改动的外部附件提供器与系统日历写入。
