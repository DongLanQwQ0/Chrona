# 重复日程

在日程详情选择「重复日程」，设置每天、每周、每月或每年重复，可指定间隔、每周的星期，以及截止日期或总次数。AI 提取使用相同的规则结构。已有系列的首次时间和规则固定；需要不同规则时停止原系列并新建。

详情入口与删除按钮并排位于日程卡片末尾，重复按钮显示当前规则或「设置重复」。重复日程页的建立勾选／停止图标放在公共标题栏右侧，停止仍先确认；已停止的系列禁用停止操作。日程名称与规则（新建时为首次时间）共用一个紧凑文本区域，长内容自然换行，不另设大标题或独立频率行。频率与结束条件按标签和值同行显示。月份使用公共日期栏，支持左右滑动、箭头和点击选日期；加载月份只更新实例列表，保留日期栏和切换动画。打开单次操作仅更新选中态，保留滚动位置和日期栏实例。

## 单次操作与停止

重复日程作为常规占位。重复详情按月列出实例，选择「编辑本次日程」进入普通日程编辑器，可修改本次标题、类型、起止时间、全天、地点、备注、提醒及待办截止；待办支持单次完成与恢复，删除操作只跳过本次。默认仅改本次，模板及其它周保持原样。日历、首页及小组件点击具体实例也进入该编辑器。

单次操作始终以原定时间识别实例，改期后仍对应同一次记录。未更改字段继承占位；显式清空地点、备注或提醒只清本次。单次编辑保留草稿保护、滚动位置、并发编辑检查及普通表单的主题与交互。

## 公告补全本次占位

AI解析请求的数据段提供已确认循环占位的稳定身份、规则及程序换算的本地时间和星期。公告明确属于同一活动系列且能识别具体一次时，返回 `occurrence_update`：目标稳定ID、原日期、公告实际提供的字段及匹配依据。主题、时间或地点变化仍可匹配原占位；公告没有明说的字段继承本次既有值，未给结束但改了开始时沿用原时长。没有明确时区时按占位时区解释公告。

解析后预览「更新本次」，必须明确确认才修改目标，不进入自动或批量新建。匹配歧义、目标消失或已被其他操作修改时保留草稿，重新解析或由用户明确选择「另建日程」；不会悄悄改成新建。确认只更新同一原实例，重复解析不会新增第二个系统日程。附属请假方式和请假期限只留主安排备注；只有请假为唯一或核心事项时才单独提取，详见[AI时间提取](../ai/ai-time-extraction.md)。

原模型时间依据不改写；提案、目标身份、匹配理由、草稿修改及应用前后值关联当次解析审计。应用后源公告保存为已应用记录，不持有主系列的系统事件关联；删除或重新解析该公告不会删除已更新的占位。源记录可进入对应本次日程。

「停止重复」停止操作时尚未开始的日程及提醒，保留历史。判断依据为改期后的实际开始时间：原定未来但已移至过去的实例保留，原定过去但已移至未来的实例停止。已经开始且尚未结束的日程保留。

日程列表以系列为一条管理记录，日历、首页时间线、小组件与提醒按查询时间范围展开实例。列表删除系列会删除整个系列；只处理一次请进入重复详情。

## 存储与系统日历

`repeat_rule`、`repeat_exceptions` 和 `repeat_stopped_at` 保存系列及异常，不预生成无限未来行。`RepeatOccurrences` 使用现有 biweekly 展开规则，先投影常规占位，再应用原实例键下的 `fields`；旧改期、跳过和完成状态保留，手工或公告编辑的前后值保存在同键 `history`。

数据库版本17增加 `occurrence_update` 操作提案，与解析成功结果同事务先持有，随后补齐投影。即使进程在两步之间中断，也不能自动新建。完整备份保留提案与解析日志；跨设备同步传操作提案及审计引用，完整本地解析日志仍不跨设备。目标冲突检查使用便携内容快照，不携带本地日历ID或提醒设置；本机已有单次提醒在同步后保留。

`RepeatActions` 为原生与网页共用写入入口，检查候选编辑基线，在同步锁内更新。系统日历使用 RRULE/DURATION 主事件与异常事件；写入失败时本地事务回滚。跨设备同步及备份保存规则、异常和停止时间，恢复时重建日历系列。

系列共用系统事件时，本次重复操作先为当前候选拆出独立事件；返回的数据携带新关联，其他候选的规则与提醒保留。新事件遵循[系统日历关联](schedule-browser.md#系统日历关联)的提交补偿规则。

## 验证

离线检查：`repeat_ai_check.py`、`repeat_projection_check.py`、`calendar_repeat_check.py`；覆盖规则提取、日期边界、夏令时、改期身份、停止历史与 Provider 写入字段。`RepeatDeviceCheck` 使用独立验证应用与自建记录，比较真实 Calendar Provider 实例和本地投影，完成后清除测试记录。实际设备结果见[验证记录](../../validation-history.md)。
