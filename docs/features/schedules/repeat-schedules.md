# 重复日程

在日程详情选择「重复日程」，设置每天、每周、每月或每年重复，可指定间隔、每周的星期，以及截止日期或总次数。AI 提取使用相同的规则结构。已有系列的首次时间和规则固定；需要不同规则时停止原系列并新建。

## 单次操作与停止

重复详情按月列出实例，支持跳过、单次改期；待办支持单次完成与恢复。单次操作以原定时间识别实例，改期后仍对应同一次记录。

「停止重复」停止操作时尚未开始的日程及提醒，保留历史。判断依据为改期后的实际开始时间：原定未来但已移至过去的实例保留，原定过去但已移至未来的实例停止。已经开始且尚未结束的日程保留。

日程列表以系列为一条管理记录，日历、首页时间线、小组件与提醒按查询时间范围展开实例。列表删除系列会删除整个系列；只处理一次请进入重复详情。

## 存储与系统日历

数据库版本 14 在候选上保存 `repeat_rule`、`repeat_exceptions` 和 `repeat_stopped_at`，不预生成无限未来行。`RepeatOccurrences` 使用现有 biweekly 展开规则；时区与首次日程一致，持续时间按固定时长保持。单次异常保存原定时间、改期时间及完成/跳过状态。

`RepeatActions` 为原生与网页共用写入入口，检查候选编辑基线，在同步锁内更新。系统日历使用 RRULE/DURATION 主事件与异常事件；写入失败时本地事务回滚。跨设备同步及备份保存规则、异常和停止时间，恢复时重建日历系列。

## 验证

离线检查：`repeat_ai_check.py`、`repeat_projection_check.py`、`calendar_repeat_check.py`；覆盖规则提取、日期边界、夏令时、改期身份、停止历史与 Provider 写入字段。`RepeatDeviceCheck` 使用独立验证应用与自建记录，比较真实 Calendar Provider 实例和本地投影，完成后清除测试记录。实际设备结果见[验证记录](../../validation-history.md)。
