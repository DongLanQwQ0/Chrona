# 重复日程合并

手机在前台自动检测重复候选，发现新组后弹出「发现重复日程」；后台解析、同步或批量入库完成后，回到前台再提示，不在后台启动窗口。已配对网页在可见、没有编辑浮层或附件操作时自动检测。无需进入设置扫描；设置中的「合并重复日程」保留为主动重新查看入口。

弹窗列出各组时间及每个成员自身的标题、地点和来源，可打开对应记录。用户按组勾选，默认不选，确认只合并所选组；「暂不合并」、返回或点外部关闭均不改候选。原生保存已展示组的内容签名，网页在当前标签页会话保存；无关原文或其它组更新不重复提示旧组，新增成员或组内容改变后重新提示。来源跳转同样视为本批已展示，后续可从设置继续处理。

预览后任何本地业务数据变化都会拒绝确认，须重新扫描并重新选择。处理中记录不参与。确认删除所选组中的重复候选实体，保留最小稳定 UUID 对应的一份；不会删除整个来源任务、原文、图片、文件或调用系统日历删除链。未选择组保持原样；提交中冻结选择和来源操作，避免重复提交。

统一原生入口为 `DuplicateScheduleReview`，由 `ChronaApp` 跟随 Activity 前后台生命周期运行；两秒检查数据 revision，仅变化后后台扫描，共用 `AndroidSync.LOCK`。网页可见时每2.5秒检测，已有浮层不被替换；扫描结果晚于页面切换或浮层变化时丢弃，留待下次检测。检测与提示不请求付费模型，不操作系统日历。

## 一致条件与追溯

`DuplicateCandidates.key` 保留原有精确业务身份：标题、绝对开始/结束时间、截止时间、地点、分类、全天、记录类型和完成状态一致。标题和地点先做 NFKC 规范化、去除空白并忽略大小写；时间逐毫秒比较。完成状态比较待完成/已完成，完成时间戳差异不影响分组。

扫描分组另支持有日期、非记录事项的宽松标题匹配：起止、截止、分类、全天、完成状态、重复规则、重复时区、单次例外和停止时间仍保持一致。标题在上述规范化基础上忽略标点；规范化后相同，或一方包含另一方且较短标题至少 4 个码点、长度覆盖较长标题至少 65%，或较短标题至少 5 个码点且归一化 Levenshtein 相似度至少 88%，均可进入预览。标题中的阿拉伯与中文数字序列必须一致，区分第 1／2 次、第三／四次及不同章节；中文数词保守按原格式比较。地点与备注相同不能代替标题条件。编辑距离只计算阈值允许的带宽，超出编辑预算立即停止。

地点忽略全半角、大小写、空白和标点；一方缺地点可与已知地点匹配，双方明确且不同的地点保持独立。未定日期项及记录只使用原有精确规则。相似关系不传递：按候选 ID、来源任务 ID 的稳定顺序分组，新成员必须与组内每一项都匹配，避免相似标题链或空地点把有冲突的事项串成一组。

来源任务、候选 ID、系统日历关联 ID、非重复事项的时区标签、备注、提醒分钟、确认标志、存疑等级和自动补结束标记的差异不阻止有日期日程合并。开始、结束和截止时间全部为空的未定日期项额外比较完整备注，记录类型始终比较完整备注，避免仅标题相同的不同内容被合并。

扫描范围为 Chrona 已保存的候选日程，跨来源候选参与同一轮比较。外部课表和系统日历 Provider 中独立存在的条目不会被枚举；只在外部显示的重复项不在本入口处理范围。

保留候选的详情列出合并来源，可打开原任务查看原文与附件。来源任务的详情可到达保留日程；目标已删除时显示明确状态。删除来源后，永久记录中的原文、来源、链接正文和候选快照仍可追溯。删除来源本身仍走用户主动的普通删除规则；合并确认从不走此路径。

合并保留一份候选，原始备注、时区、存疑等级和自动补结束标记保存在来源快照中供追溯和同步。被移除候选的系统日历关联 ID 单独保留在本机合并记录中；关联 ID 和提醒设置不跨设备同步。合并不改 CalendarContract.Events/Reminders，不删除系统日历事件；已有多个系统事件及其提醒仍由系统日历管理。未写入候选也不创建额外通知。小组件在成功提交后刷新。

## 事务、身份与同步

数据库 v10 增加 `candidate_merges`，只含不可撤销审计记录与设备本地关联 ID。扫描/确认与 WebDAV、LAN 共用 AndroidSync.LOCK，在后台等待；预览 revision 和事务同时验证，先校验全组再删除，一处失败整体回滚。来源/附件身份及映射不改。

共享协议增加独立 `merge_<sourceCandidateUUID>` 内容，包含稳定来源/目标 task、candidate UUID 与来源快照。去向严格小于来源 UUID，禁止自环/环。并发去向选择较小目标，版本向量取并集；链式标记最终收敛，永不被来源删除、冲突版本选择或旧任务包撤销。没有恢复合并入口。

接收端先接受永久标记，再应用任务；已删除 UUID 不插入，marker/task 乱序也成立。应用 marker 的同一事务仅从 source task 已应用 baseline 中过滤对应 UUID，保留原文/附件/其他候选与 baseline_clock；任务应用也保存过滤后的基线。合并造成的删除不会冒充本地编辑，真实原文/附件修改仍触发原有并发保护。来源或保留任务删除后，marker 继续存在。

备份保存审计与映射。恢复先为仍存在但尚未映射的实体固化原 UUID，再轮换 sync_meta.identity，避免恢复 sqlite_sequence 后新实体重复使用备份后的旧云端身份；已有实体及 marker 的 UUID 不变。设备 head 身份重置、自动同步关闭，版本差异由手动同步确认。

所有同步设备必须升级到 0.14.4 或更新版本后使用合并。0.14.3 及更早不支持 merge 类型，会拒绝同步内容；不提供兼容删除/忽略标记的回退。收到不支持类型的新客户端会提示升级所有设备。

## 验证

`python checks/candidate_merge_check.py` 编译真实 TaskStore、CandidateMerges、共享模型和提取的 AndroidSyncData staging/apply/changed 方法，Android SQLite API 替身通过 UTF-8 管道连接 Python 标准 SQLite。覆盖中文／英文／全角与标点、标题后缀与包含覆盖、编辑距离阈值、码点长度、数字冲突、缺地点与地点冲突、非传递分组、业务字段差异、不同关联 ID 和来源元数据、未定日期/记录备注保护、宽松匹配的实际预览与确认、跨来源、过期预览、强制失败回滚、任务/附件保留、来源/目标删除、旧包重放、新设备/乱序、链式并发、远端合并同时更新原文/附件、真实本地修改保护及恢复身份重用。此检查不模拟系统 Provider 或 Android UI。

`CandidateMergeCheck` 额外覆盖多组选一、空选择不删除、未知组拒绝与未选组完整保留。网页 `node checks/lan_web_check.cjs --merge-only` 用现有 Edge 与模拟手机 API 检查自动提示、默认不选、取消／无关 revision 去重、预览、过期拒绝/重扫、确认与来源导航。原生隔离模拟器入口为 `check=compact_detail_atomic / scope=automatic_merge`，检查前后台自动发现、取消去重及真实 SQLite 按组提交；不操作用户手机。真机日历提醒、多台手机 WebDAV、升级仍需单独验收。
