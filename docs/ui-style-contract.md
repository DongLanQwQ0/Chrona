# UI 设计规范

适用于整个应用的页面、卡片、表单、浮层、导航和动态状态。采用主题亚克力、轻圆角、紧凑层级和连续交互。具体已确认参数见[交互基线](ui-interaction-baseline.md)，功能行为见对应[功能文档](README.md)。

## 一致的视觉语言来自公共组件

颜色、表面、字体、圆角和反馈由公共设计系统提供。新增界面组合现有组件；组件存在缺陷时在其职责范围内修正，避免逐页复制另一套实现。图标使用统一 Lucide 资源，主操作、选择态和强调内容使用当前主题色；深浅主题下保留清晰对比。

| 职责 | 公共入口 |
| --- | --- |
| 页面结构、安全区与标题 | `SettingsPageLayout.content/header/show` |
| 配色、文字、卡片和表单 | `UiStyle.colors/title/muted/card/input/button/toggle` |
| 浮层、长内容和开合 | `UiStyle.dialogPanel/dialogBody/showFloatingDialog` |
| 选择与导航 | `DockNavigationLayout` 及其 motion host |

## 布局遵循同一内容轴和间距层级

页面先确定内容区域，同组控件共享对齐轴和宽度策略；可用宽度由容器统一分配，而非各控件临时计算。同级表单行视觉高度一致，多行内容按需要增高。紧凑通过信息取舍和内部间距实现，不挤压文字、缩小操作区域或制造大块空白。

布局、绘制和触控范围分别管理。动画的空间由层级与绘制区域承载，不反过来挤窄静态内容或永久撑高每行。中间容器容纳其子项的完整动效，最终视口仍保护真实边界；优先复用组件提供的承载方式。

现有尺寸基准统一由公共组件维护：

| 对象 | 正常字号下的基准 |
| --- | --- |
| 页面内容 | 左右各 20dp；公共标题后至少 16dp |
| 内容卡片 | 圆角 10dp；内距水平 16dp、垂直 12dp；相邻记录 8dp |
| 浮层 | 圆角 12dp；内距 20dp；标题与正文 12dp；分组 12–16dp |
| 表单与图标操作 | 单行最小 54dp；图标触控区 48dp、图标 24dp；相邻操作间隔 8dp |
| 文字 | 页面标题 24sp、浮层标题 21sp、卡片标题 16sp、次要信息 13sp |

尺寸使用 dp/sp。大字体与窄屏按内容自然适配，保留可读性、滚动与可达操作。不同长度的选项可有不同内部宽度，高光连续适应实际范围；整体对齐不能以文字换行、挤压或过度缩小为代价。

## 信息按任务与重要程度组织

标题、当前值、时间、来源与状态有明确层级。次要信息使用文字样式区分，整张卡片保持可读。内容容器适应信息长度。输入框和普通按钮使用 8dp 圆角，筛选标签使用 6dp 圆角。选择栏保留已确认的圆端高光及独立 28dp 底板，不把其动态几何推广到普通控件。

仅保留帮助用户理解、决定或操作的内容，避免重复说明与无用副标题。列表可省略长内容，但详情必须能完整查看。状态同时通过文字、图标或无障碍语义表达，不能只凭颜色判断；未知与未完成保持不同含义。

## 交互反馈连续，数据状态可信

按下、拖动、释放、取消和反向操作从当前视觉状态接续。位置、大小、颜色和透明度平滑变化，避免闪切、目标附近抖动和中间帧跳回。动效服务于操作关系，不替代真实状态更新；系统减少动画时仍可完成操作。

局部数据变化保留未变内容、滚动位置、输入与焦点，通过布局过渡呈现增删和位移，避免整页重建或重播入场。背景采样、圆角和模糊随真实位置与形状同步，效果层不能产生硬边、接缝、边缘光点或残留遮罩。

操作范围与视觉含义一致：点击、切换和查看不互相触发，选中态反映真实值，隐藏内容不留无意义空位或仍可点击的区域。业务启用条件、来源范围与权限由统一业务规则管理，直接跳转和缓存页面也遵守同一规则。

## 变更边界与完成标准

以用户明确要求和已确认基线为准。不得借修复裁切、性能优化或个人审美增加限制、隐藏条件或改变功能含义；发现歧义先核对上下文，额外取舍先提出再实施。

修改前读完整的目标区域和公共组件，修改后检查实际画面及关键交互，覆盖主题、内容长度、字体适配与连续操作造成的变化。检查聚焦本次影响，避免重复无关测试。编译和替身检查支持代码结论，实际呈现需要渲染证据；不能完成时记录缺口。以上一致性、可读性或交互连续性仍有缺陷时，该区域尚未完成。
