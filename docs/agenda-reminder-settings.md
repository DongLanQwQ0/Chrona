# 日程来源与提前提醒设置

设置中的“系统日程”入口汇总首页与日历页的显示开关。原页面开关保留，共用各自的偏好；日历沿用原 Activity 的同名偏好文件与 system 键，不复制或迁移状态。首页、日历、小组件、提前提醒的系统来源彼此独立。

提前提醒按以下顺序决策：

1. “开始前30分钟提醒”关闭：不发送，结束已有提醒并取消下一次闹钟。
2. 系统来源且“提醒包含系统其他日程”关闭：不读取、不提醒，也不进入原子通知。它优先于系统日程原子通知开关。
3. vivo、自有场景已启用、系统通知权限允许，且该来源的原子通知开关开启：使用原子通知。Chrona与系统来源分别选择。
4. 其余已允许提醒的日程使用普通常驻提醒；系统通知权限未允许时不发送。

原子选项默认开启以保留既有提醒方式。不可用、总开关关闭或系统来源被禁止时，相应原子选项禁用，但保留其选择。通知权限、场景能力在后台读取，界面返回及通知授权后重新检查。切换通知形式时，先结束并取消旧卡片，再用同一槽位发送新卡片，避免关闭原子选项后残留原子岛。

合并重复日程页与其它二级设置页复用公共标题栏，标题栏下方至少16dp留白，左右内容各20dp。规范见 development.md 与 AGENTS.md。

胶囊在开始前最后两分钟显示系统秒级倒计时；活动结束前也采用同样显示。非活动日程开始后保留“已开始”最多三分钟，然后关闭并从提醒候选中排除，实际日程的结束时间不延长此提醒窗口。活动继续进度直至结束。分钟级刷新按固定过期时间重新计算超时，不会从刷新时刻重新计三分钟。
