# 项目基本要求

本文件定义全项目共同遵循的产品、工程和交付原则。功能细节见[功能文档](README.md)，视觉与交互见[UI 设计规范](ui-style-contract.md)。用户最新明确决定优先，文档同步反映决定。

## 以用户数据和可用闭环为中心

记录、解析、审核、写入、提醒、修改与删除构成同一条闭环。修改一个环节时检查相关入口、状态回调和恢复路径，保留原文、来源和可追溯关系。推断保留为可确认的建议；未知值保持未知，不伪造时间、状态或外部能力。

本地已保存内容应能及时打开，网络刷新与页面呈现分离。外部来源使用稳定身份更新，去重依据业务含义而非来源标签；原始数据、展示聚合与实体合并须区分。功能的启用、权限和来源选择在各入口一致生效，查看内容不隐式改变设置。

## 保持简单、统一且职责明确

优先局部修复、现有依赖和公共组件。共享状态、查询、持久化、网络与界面各有明确职责，避免页面私有实现绕过统一规则。对真实错误处理并保留可恢复状态，不增加假设性的配置、兼容层或静默降级。

后台与异步工作遵守生命周期、请求身份和取消边界；旧结果不得覆盖新选择。保持输入、焦点、滚动和未变内容的身份，局部变化局部更新。性能优化先取得证据，再减少实际开销，保持已确认行为与画面。

## 保护数据、凭据和现有环境

修改前检查当前变更并准备可恢复备份。持久格式变化须明确升级与恢复策略，覆盖安装保留既有签名和数据；禁止通过卸载、清空或重建用户数据掩盖缺陷。

密钥、密码、Cookie、配对凭据与私人测试素材不进入仓库、日志或公开产物。外部服务调用、设备操作和敏感验证遵守用户当前授权。新增或更换工具链先确认；本机路径和缓存配置见[开发指南](development.md)，不随意修改全局环境。

手机主目录及下载、图片等公共目录禁止写入测试文件，包括测试APK、截图、录屏、层级XML、日志和夹具。优先通过stdout直接回传项目目录；设备端确需临时落盘时，仅使用应用专属测试目录（优先cache／externalCache），或明确命名的`/data/local/tmp/chrona-validation/`，读取后在finally清理。不得使用工具默认的`/sdcard/window_dump.xml`等公共输出路径。已有临时项按确切自有路径清理，不递归清空公共目录，不把正常用户导出当作测试垃圾。

## 按影响验证，准确说明结果

完成相关实现后集中验证核心路径及实际失败路径，复用同一候选的有效证据。文档修改检查内容、链接和差异；代码修改按影响执行构建、检查与必要的实际渲染或设备操作。

分别记录实现、编译、离线逻辑、真实交互和外部服务验证。无设备或无权限时明确实际缺口；已有局部证据不推广为全场景通过。只交付已完成的结果和影响使用的限制。

## 文档只维护一份当前事实

README 介绍产品；使用指南服务用户操作；开发指南组织构建和功能入口；通用规范描述全局原则；功能文档描述业务契约。交接页只写当前状态，更新记录和验证记录按版本保存事实。过时计划和重复过程笔记退出当前入口；有追溯价值的内容进入归档，归档不产生新要求。

执行纪律及反馈要求由仓库 `AGENTS.md` 维护，开发流程见[开发指南](development.md)；`HANDOFF.md` 是唯一当前工作单。总结须把决定写回对应规范，给接续者留下候选、有效证据、实际缺口及可执行的下一步，不另建重复规则或长篇待办。公共 UI 的职责和接入由[公共 UI 库](ui-library.md)维护。
